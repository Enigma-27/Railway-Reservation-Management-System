# Change report 14: frontend design overhaul

Branch `final-few-changes`. Nothing was committed or pushed. No API route, payment, refund or booking rule changed.

## 1. Design system
- **Tokens**: `frontend/public/rrms-theme.css` (dark default, light via `data-theme`), colour channels for Tailwind in `frontend/public/rrms-palette.css` (generated by `frontend/scripts/gen-palette.mjs`), mapped in `tailwind.config.js`. Staff and admin pages (plain Tailwind) follow the theme without page-by-page edits.
- **Palette**: navy / near-black base, amber highlight, blue kept for buttons and links. Status colours (confirmed, RAC, waiting, cancelled, delayed) in one place, mapped by `src/ui/status.ts`.
- **Fonts** (npm, bundled, offline): Fraunces (serif + italic accent), Inter, JetBrains Mono.
- **Motion**: CSS + IntersectionObserver, no animation library (allowed by the brief). transform/opacity only; `prefers-reduced-motion` gives static text and no movement.
- **Theme toggle**: sun/moon in every header, `localStorage` in try/catch, system preference on first visit, no flash (script in `index.html`).
- **Results**: axe (wcag2a, 2aa, 21a, 21aa) on 94 page x theme combinations (public, 9 passenger, 11 staff, 24 admin; dark and light) at 1366x768 AND again at 390x844: **0 violations**, no sideways page scroll at 390. Hero text over the photo, worst-pixel contrast measured: headline 11.2, amber word 9.1, paragraph 9.5, stat labels 11.8, note 6.2 (min over both themes and both sizes; the hero keeps a dark overlay in both themes).

## 2. Landing page
Header (Home, Train Info, Live Trains, Contact, Ctrl+K, alerts bell, theme toggle), alerts strip, hero with typed headline (Easy, Reliable, Live, Simple), train search (custom Select and DatePicker), one sign-in card, stat strip from the real `GET /api/live-trains` (trains running today, seats available, on-time %, count-up, live dot), three big cards (Book a ticket, Live Trains, PNR status with the quick check), "how it works" with a train moving along a route line, "one system, three portals" linking to the sign-in, footer.
- Sign-in: role tabs with a sliding indicator; fields empty by default (autocomplete off); "Use demo account" fills the chosen role; changing role clears; "New passenger? Create an account" kept.
- PNR quick check uses the real PNR API. A PNR is private, so a signed-out visitor sees "Sign in to check it" (backend rule unchanged).
- Contact: floating button removed completely (`rrms-contact.js` deleted). "Contact" link in header and footer opens a slide-in drawer (same form, same endpoints). Nothing floats over content anywhere.

## 3. Roles and shared layout
`src/layout/PortalShell.tsx` is the one skeleton. Passenger = blue, Station staff = green, Admin = amber: thin top bar, role badge by the profile menu, sidebar label (Passenger / Station staff / ADMIN MODE), tab title `RRMS - Admin | Page` and a role-coloured tab icon. Profile menu top right, theme toggle next to it, bell, Contact in the footer.

## 4. Passenger migration
- **Moved to React**: shell (sidebar, top bar, breadcrumb, footer), the URLs (`/passenger`, `/book`, `/bookings`, `/pnr`, `/profile`, `/tdr`, `/grievances`, `/alerts`, `/live-trains`), sign-out, badges, toasts, Live Trains, Ctrl+K. Old `/user/*` redirects to `/passenger`. The separate static app and its theme copy are gone.
- **Kept and only restyled**: the page controller `src/passenger/legacy/app.js` (+ `passenger-step.js`, `services/apiService.js`): 6-step booking, Razorpay checkout, Pay now / resume / cancel unpaid, My Bookings and cancellation, TDR, saved passengers, PNR enquiry, profile, every API call. **Why**: a rewrite of the payment code is the risk the brief warned about.
- **Changed in `app.js` (shell wiring only)**: `DOMContentLoaded` became exported `bootPassengerApp()`; `navigateTo` asks the router; sidebar/top-bar DOM access removed or null-safe; counters sent as the `rrms:pax-counts` event; toast sends the shared `rrms:toast` event; modal overlay binding is a function. Styles: old stylesheet scoped under `.pax-legacy`, colours mapped to tokens, shell rules dropped.
- Verified in the browser: Live Trains -> "Book this train" -> booking results with the train preselected; search; passengers; summary; payment screen with Pay now and Cancel unpaid; cancel unpaid; My Bookings, PNR, TDR, Alerts, Grievances, Profile; theme toggle; logout.

## 5. Live Trains in each portal
`LiveTrainsView` (same data, filters, detail panel, 15 s refresh, live dot + last updated) is in the passenger, staff (`/staff?tab=live-trains`) and admin (`/admin/live-trains`) sidebars and the public page. Passenger button continues into booking; staff/admin also see chart state and occupancy.
